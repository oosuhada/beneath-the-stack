# v0.1 audit — what was real, and what was still too shallow

The first release established a useful contract: the browser only observes evidence produced by
executable C++ labs. Before expanding it, v0.1 was audited against the stricter goal of becoming a
long-running computer-systems mastery laboratory.

| Area | v0.1 finding | v0.2 response |
| --- | --- | --- |
| From-scratch structures | Hash table, binary heap, graph traversal and B+ tree were genuine implementations rather than STL wrappers. | Keep them; add a custom dynamic array, linked list, stack, queue, BST, trie and union-find. |
| Correctness | Tests covered core happy paths and a few invariants, but not enough ownership, malformed-input, persistence or boundary cases. | Add `tests/mastery_tests.cpp` for copy/move/destruction, parser rejection, persisted reopen, duplicate keys and state-machine hysteresis. |
| Benchmarks | Warm-up/repetitions/p50/p95/mean/stddev were recorded, but optimization flags were implicit and v0.1 JSON was the only structured release format. | Evidence schema v2 records compiler flags + commit SHA and emits normalized CSV as well as JSON. |
| Networking | POSIX TCP and HTTP/1.1 keep-alive were real, but request handling was effectively header-string inspection. | Add a hand-written request-line/header parser, connection-pool reuse and an observable receive-timeout failure path. |
| OS | Concurrency existed, but there was no process, file-descriptor or syscall-boundary experiment. | Add `fork`, `pipe`, `waitpid`, `dup`, process isolation and syscall-cost observations on macOS/POSIX. |
| Memory | No direct layout/locality experiment existed. | Compare contiguous storage with pointer chasing, and stack-frame storage with heap allocation while preventing compiler elimination. |
| Database internals | The B+ tree lived only in memory. It did not answer where rows live. | Add fixed-size row serialization, 4 KiB pages, a pager file, reopen/index rebuild, page scan and indexed page lookup. |
| Interview docs | Explanations were technically useful but product connections were mostly prose. | Introduce the fixed questions **What? Why? Failure? Where used?** and link real repository evidence. |
| Progress | `applied` could mean “used in a toy scenario,” which overstated real-world transfer. | Redefine level 5 to require a concrete existing-product artifact or committed change. |
| Visualization | The dashboard was already thin and read JSON generated by binaries. | Keep it thin. New work goes into implementations/tests/docs; no v0.2 UI expansion is required. |

## Benchmark lesson from the audit

The v0.2 memory-locality experiment initially produced near-zero timings for predictable contiguous
and stack work. That was rejected rather than published: the compiler had enough information to
remove or constant-fold the work. The final experiment uses no-inline functions and observable
memory accesses so the timed region actually performs the intended reads/writes.

The rule is now explicit: **a benchmark that measures optimized-away work is a failing experiment,
not an impressive number.**

## Scope discipline

This audit also rejected several tempting but weak extensions. A priority queue was not inserted
into Elevator Queue Lab simply because this repository contains a heap: that simulator has only six
cars and continuously changing policy scores, so a heap is not automatically the better structure.
Likewise, the embedded track does not claim GPIO, interrupts or firmware experience without
physical hardware. v0.2 only builds a deterministic HAL/state-machine seam that real hardware can
later implement.
